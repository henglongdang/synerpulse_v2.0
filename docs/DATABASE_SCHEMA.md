# Database Schema

PostgreSQL. The source of truth is `apps/api/src/db/schema.ts` (Drizzle). Migrations are SQL files in `apps/api/drizzle/`, generated with `npm run db:generate -w @familypulse/api` and applied at startup or with `npm run db:migrate`. The same migrations run on PGlite (development and tests) and PostgreSQL (production).

## Conventions
- UUID primary keys, generated by the application.
- Money is stored as `bigint` cents, and so is every signed amount. Percentages are integer basis points (inside JSON rule actions).
- Calendar dates use `date`; instants use `timestamptz`. Rows carry `created_at` and, where they change, `updated_at`.
- Every household-owned table has a `household_id` foreign key with `ON DELETE CASCADE`, so deleting a household removes all of its data.
- Users are never cascaded into shared financial data. Authorship columns (`created_by`, `editor_id`, …) are `SET NULL`, so records survive a member leaving.

## Entity overview

```
users ─┬─< sessions
       ├─< password_reset_tokens
       └─< household_members >─ households ─┬─< categories ─< member_category_scopes (member × category)
                                             ├─< invitations
                                             ├─< accounts ─< transactions ─┬─< transaction_tags
                                             │                             ├─< transaction_revisions
                                             │                             ├─< transaction_comments ─< comment_mentions
                                             │                             └─< attachments
                                             ├─< recurring_items (→ account, category)
                                             ├─< budget_plans ─< budget_items (→ category)
                                             ├─< goals ─< goal_contributions (→ transaction?, rule?)
                                             ├─< rules
                                             ├─< scenarios
                                             └─< activity_events
users ─< notifications (→ household?)
```

## Tables

| Table | Purpose | Notable columns and constraints |
|---|---|---|
| `users` | Accounts | `email` unique on `lower(email)`; `password_hash` (Argon2id); `notification_prefs` jsonb; `last_household_id` |
| `sessions` | Server sessions | `token_hash` unique (SHA-256 of the cookie token); `expires_at`, `last_seen_at` (sliding); `user_agent` |
| `password_reset_tokens` | Single-use reset | `token_hash` unique, `expires_at` (30 min), `used_at` |
| `households` | Shared space | `currency` (ISO code, labels amounts), `timezone` (IANA, defines the household's "today"), `is_sample` (demo data flag), `onboarded_at` |
| `household_members` | Membership and role | PK (household, user); `role` in owner/admin/contributor/viewer (CHECK); **partial unique index: one owner per household** |
| `member_category_scopes` | Contributor edit limits | PK (household, user, category); composite FK → `household_members` |
| `invitations` | Invite links | `token_hash` unique; `email` (optional lock); `role` (never owner); `category_scope` jsonb; `expires_at`, `accepted_at`, `revoked_at` |
| `categories` | Spending and income categories | `group` CHECK (living/entertainment/unexpected/income); unique `(household_id, lower(name))`; `archived_at` |
| `accounts` | Checking, savings, cash, credit card, loan, investment, other asset | `visibility` shared/private and `owner_user_id`; `opening_balance_cents` and `opening_date` (balance = opening + Σ transactions); `credit_limit_cents`; `provider` manual/csv; CHECKs on type, visibility, `last4` |
| `transactions` | The ledger | `type` expense/income/transfer/adjustment; signed `amount_cents` with a **CHECK that the sign matches the type**; `version` (optimistic concurrency); `transfer_group_id` (links both legs); `source`; `recurring_id`; `deleted_at` (soft delete); **partial unique** `(household_id, client_request_id)` (idempotency) and `(account_id, import_hash)` among non-deleted rows (CSV duplicates); indexes on (household, date), (account, date), category, transfer group |
| `transaction_tags` | Tags | PK (transaction, tag); index on tag |
| `transaction_revisions` | Version history | unique (transaction, version); `action` created/updated/reverted/deleted/restored; full `snapshot` jsonb plus `changes` jsonb; `editor_id` |
| `transaction_comments`, `comment_mentions` | Asynchronous discussion | Mentions are normalised (PK comment × user) |
| `attachments` | Receipts | `storage_key` (random; the filename is metadata only), `mime_type`, `size_bytes` |
| `recurring_items` | Bills and income schedules | `kind` bill/income; `frequency`; `anchor_day` (month-end safe); `next_date`; `min_amount_cents` (conservative income); `autopay`; `active` |
| `budget_plans`, `budget_items` | Monthly limits | A plan is unique per (household, `month` "YYYY-MM") and **carries forward** until a later plan exists; items have PK (plan, category) and CHECK amount ≥ 0 |
| `goals`, `goal_contributions` | Saving goals | Saved total = Σ contributions; contributions may be negative (withdrawals), non-zero CHECK, and may be linked to a transaction and rule (automatic allocations) |
| `rules` | Automation | `conditions` and `actions` jsonb (validated by Zod on write); `priority`; `times_applied`, `last_applied_at` |
| `scenarios` | Saved what-ifs | `horizon_months`, `granularity`, `income_mode`, `adjustments` jsonb |
| `notifications` | In-app inbox | **partial unique `(user_id, dedupe_key)`** makes alert evaluation idempotent |
| `activity_events` | Audit feed | `visible_to_user_id` (set for events about private accounts); index on (household, created_at) |

## Derived values (not stored)
- **Account balance:** `opening_balance_cents + Σ amount_cents` over non-deleted transactions.
- **Net worth at date D:** for accounts opened on or before D, opening balance plus transactions dated on or before D. Negative balances count as liabilities.
- **Budget usage:** Σ spending per category within the month (shared accounts), compared with the plan in effect.

## Migrations and seed
- `0000_init.sql`: the full schema above.
- `0001_household_timezone.sql`: adds `households.timezone` (default `UTC`; additive and safe).
- `npm run db:seed` loads **one fictional household** ("Okafor-Lin Household", `is_sample = true`) with six months of generated activity. It refuses to run against a production database unless `--allow-production` is passed. `npm run db:reset` wipes the development database (PGlite directory, or `drop schema` with `--yes` on Postgres; disabled in production).
